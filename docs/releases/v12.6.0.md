# Zotero PaperFlow 12.6.0

Release date: 2026-10-25. This backward-compatible minor release adds a recovery interface for saved concurrent-edit drafts. No database migration is required.

Adds recovery of saved concurrent-edit drafts with a localized entry in the native Zotero settings pane, opening a dedicated settings-only window. Fixes host initialization when Gecko wraps standalone-window arguments. Compare the baseline, local draft and latest on-disk values, explicitly choose every conflicting field, then review all changes, including independent local edits, before confirming recovery. Missing values, null values, record deletion and order conflicts remain distinct. Credentials are masked in the comparison.

恢复入口：**Zotero 设置 → Zotero PaperFlow → 数据与同步 → 比较并恢复冲突草稿**，然后选择 **刷新草稿 → 比较 → 逐字段选择 → 预览恢复 → 确认恢复**。比较时不预选任何值；预览会列出自动合并的独立编辑。恢复前单独备份当前数据库，原冲突草稿保留，不覆盖既有导入前备份。

Both preview and confirmation verify the original draft and the latest database bytes. Changed data, expired previews and unsaved edits in the current workspace block recovery. The host serializes recovery with ordinary saves. A resolved receipt prevents repeated restoration after restart; receipt-write failures report a warning after a successful recovery rather than falsely reporting a failed database write.

Limits: drafts without a baseline remain available on disk but cannot use field recovery; malformed drafts are preserved. The list shows the latest 100 drafts. Individual files over 32 MiB or comparisons over 500 rows are blocked. Displayed values are limited to 12,000 characters per side and clearly marked if shortened; originals remain intact. Host operations use a ten-minute preview lifetime and retain at most eight inspection/preview tokens. Direct external writes after the final disk check are outside the in-process queue; close other applications that edit this file during recovery.

Validation: 90 Node regression tests, seven release-package tests, release-tag syntax/version self-check, source-to-XPI payload/hash verification, and isolated Windows Zotero 10.0.6 acceptance (10 first-launch checks and two restart checks). First-launch checks cover installed identity, real conflict creation, UI choices, actual message bridge, four theme/width combinations, previews, unsaved-edit guarding, recovery, navigation and the actual native-preferences entry; restart checks cover persisted data, backup, original draft and resolution receipt. Synthetic records only; no primary-profile installation or live cloud synchronization was performed. Detailed development evidence remains in workspace `output/paperflow-conflict-recovery-20261025/`.

Also includes the previously unpublished 12.5.6 cloud preflight fix: when a GitHub database file appears between reads, merge its existing contents before updating it with the matching SHA. Local regression coverage uses controlled GitHub responses.

Existing add-on IDs, storage format, preference keys and declared compatibility bounds are preserved. Native acceptance in this run covers Zotero 10.0.6 only.
